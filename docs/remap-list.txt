=============================================================================
WHERE THINGS GO — the two systems this list feeds
=============================================================================

1. Compression dictionary (core/compression/dictionary.py) — the fallback
   rule-based prompt compressor used when no OPENAI_API_KEY is configured.
   Two tiers:
     - PHRASE_REMAPS: exact phrase -> replacement, always applied (level 1+).
       For idioms/fillers/questions that collapse to one fixed shorter form.
     - COMPACT_PATTERNS: word-boundary regex, applied at level 2+ only. For
       REQUEST OPENERS ("can you", "would you", "is it possible to") where
       the phrase and the verb that follows are separable — strip just the
       opener so "can you find the file" -> "find the file", not "".
   Rule of thumb: if the phrase's meaning is fully separable from whatever
   follows, it collapses in PHRASE_REMAPS or gets an opener-strip in
   COMPACT_PATTERNS. If the phrase itself carries a distinct meaning that a
   generic replacement would erase (uncertainty, urgency, "how" vs "what"),
   it gets a shorter phrase that keeps that meaning — never a blind delete.

2. Friction miner (core/friction/miner.py) — detects frustration/escalation
   signals in transcripts. Most of your profanity block (fuck, shit, wtf,
   goddamn, etc.) was already covered here. Two real gaps got filled: bare
   "dammit/damnit/damn it" (only the "god damn" family was covered before)
   and "piss/pissed".

Uncertainty markers (still signal "not decided" — an agent reading the
compressed form must not think this is a settled instruction):
  not sure which / about that -> unsure which / about that
  i'm not sure -> unsure          i'm not certain -> uncertain
  i don't know yet -> TBD         i have no idea / clue -> no idea / clue
  i don't know about that -> unsure about that
  i don't know what to do next -> next steps unclear
  any ideas about -> ideas on
  what do you suggest / what would you suggest -> suggestions
  how would you go about / how should i go about -> how to
  not able to recall -> can't recall
  i can't remember -> can't remember    i don't remember -> don't remember
  i don't have access -> no access      i can't find -> can't find
  i have no preference -> no preference  it's your call -> your call

Real questions — shortened, kept as questions:
  how do we / is there a way to -> how to   (still asks for a METHOD, not
    an action — different from "can you", which asks for the action)
  how did we / when did we / what did we -> how'd / when'd / what'd we
    (contraction preserves the past-tense auxiliary a blind "did" strip
    would break — "how we decide" is ungrammatical, "how'd we" isn't)
  what do you think / what are your thoughts -> thoughts
  when's a good time / when is a good time / tell me a good time /
    tell me when it's best -> best time
  what's the status / what is the status -> status
  find me some -> find            give me details on -> details on

Substantive descriptors — trimmed, meaning intact:
  a key factor -> key factor      a big part of -> big part of
  critically important -> critical   the one thing -> one thing
  more than i can handle -> too much

Task-framing context — compressed to a short label, not deleted (the fact
that it's a boss request or a new task is real information):
  my boss asked for -> boss wants
  i have a new task / assignment / request -> new task / assignment / request
  help with an assignment -> assignment help

Urgency / deadline-pressure — canonicalized to one consistent marker rather
than deleted. This is a real priority signal; collapsing five phrasings
("this is a big deal"/"huge"/"a huge deal"/"massive") to one marker is
arguably an improvement, since an agent parsing many compressed prompts
sees one recognizable flag instead of five variants:
  this is urgent -> urgent
  this is a big deal / huge / a huge deal / massive -> high priority
  i don't/do not have much time / i'm running out of time -> time-limited
  i've/i have run out of time -> out of time

need their own entries — the bare opener strips above already handle them,
leaving the real verb ("find", "tell me", "give me") intact.

=============================================================================
BUGS FOUND ALONG THE WAY (fixed, not just noted)
=============================================================================

- "would you be able to convert this" only stripped "would you", leaving
  "be able to convert this" — the compound phrase never fired because the
  shorter "would you" pattern (earlier in dict iteration order) consumed
  its own text first. Fixed by adding a standalone "be able to" strip.

- "you betcha" got corrupted to "you b...ha" — the pre-existing bare "etc"
  entry has no word boundary and matches inside ANY word containing that
  substring (also affects "fetch", "sketch" — a real, general, pre-existing
  bug, not specific to what I added). Fixed at the root: _apply_phrases now
  anchors every phrase with a leading \b, so short entries can't match
  mid-word. Full suite still passes after this change.

- "i can't thank you enough" left a dangling "i " behind, and separately
  "to make a long story short" was getting cut mid-phrase by the shorter
  "long story short" entry, producing "To make a in short,, it broke" —
  both were phrase-ordering bugs (a shorter phrase defined earlier matched
  as a substring of a longer one defined later). Fixed by ordering longer
  phrases first, and by dropping trailing commas/colons/question-marks from
  several replacement values ("ultimately," -> "ultimately", "thoughts?"
  -> "thoughts") after finding they double up with punctuation already in
  the source text ("At the end of the day, we ship" -> "ultimately,, we
  ship", "What do you think? Now what" -> "thoughts?? Now what"). One
  pre-existing entry has this same cosmetic issue and predates this pass —
  "just to be clear" -> "clarify:" — left alone since it's not something
  this pass introduced, flagged here in case you want it cleaned up too.

- A handful of new entries were silently dead code — defined but
  unreachable because a shorter, more general phrase earlier in the dict
  always fired first (e.g. "i need to get this completed by" was shadowed
  by the pre-existing bare "i need to"). Removed rather than left in as
  misleading no-ops. Not correctness bugs (output was still fine, just
  less polished than intended), but worth knowing the dict has this
  ordering sensitivity — check anything you add later against what's
  already there.
