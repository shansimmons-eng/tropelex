Tropelex Documentation

Persistent memory system for AI agents. Store decisions, track patterns, and maintain project context across sessions. The same mechanisms double as auditable safety infrastructure — see SAFETY.md for how.

Getting Started

1. Create a Project

Projects are the top-level container for all memory. Go to Memory in the sidebar and click New Project.

2. Record Decisions

Decisions are the foundation. Click + Add Decision in the Memory section. Each decision has:

  • Decision text — what you decided (e.g., "Using Python + FastAPI for backend")
  • Context — why you decided it (optional but recommended)

3. End Sessions

When you finish a work session, click + End Session to summarize what you did. This helps Tropelex learn your patterns.

4. Configure API Keys (Optional)

For web research features, set these environment variables:

  • BRAVE_SEARCH_API_KEY — for Brave Search (free tier available). Also used by citation-grade Deep Research when set, in preference to the free but more rate-limited DuckDuckGo default.
  • OPENAI_API_KEY — for embeddings and LLM-backed features (query refinement, hybrid research merge, AI compression) — optional, dictionary/concatenation fallbacks exist

Features

Tropebook

Research knowledge base. Add citations, search locally or on the web, and build a knowledge graph.

Memory

View and manage project memory — decisions, sessions, preferences, and patterns.

Patterns

Auto-detected patterns from your usage. Tropelex learns what categories you work in, what days you're most active, and more.

Knowledge Graph

Visual D3 force-directed graph of decisions and their relationships (supersedes, caused_by, related_to).

Health Dashboard

Project health score based on decision confidence, session coverage, and pattern detection accuracy.

Impact Analysis

See which decisions have the most downstream impact and track reversal rates.

Ghost Decisions

Detect when code silently drifts from documented decisions. Compares decision keywords against git diffs.

Pre-Write Guard NEW

Check a proposed diff against active decisions before writing code. Prevention is better than detection.

"Why Do We...?" Chat

Ask natural language questions about architectural decisions. Fuses RAG + decision tree + impact analysis into causal answers.

Agent Handoff

Generate role-aware context bundles when one agent hands off to another. Token-budget-aware, role-specific.

Friction Mining NEW

Detect frustration signals in session transcripts — rephrasing patterns, retry loops, escalation markers. No explicit logging needed.

Rationale Check NEW

Fact-check decision rationale against the live web. If your rationale is "chose Postgres for JSON support," Tropelex checks if that's still true.

Memory Compaction NEW

Collapse superseded decision chains into epoch summaries. Keeps memory lean as projects age.

Context Prefetch NEW

Predict the ideal minimal context bundle for a task, sized to a token budget, prioritized by impact score.

Cost Ledger NEW

Track actual dollars and tokens spent per decision. ROI scoring with real denominators.

PR Bot NEW

Generate PR comments with relevant decision context and ghost warnings. Distribution channel for insights.

Narrative Mode NEW

Generate readable prose from the decision graph. Audience presets: new hire, investor, product manager.

Decision Market NEW

Place confidence bets on decisions and track calibration over time. Gamifies retrospective honesty.

Slack Capture NEW

Capture decisions from chat messages and extract implicit decisions from threads.

Time Travel NEW

Check out project memory as of any past date. Forensic tool for postmortems.

Contradictions NEW

Scan for unresolved contradictions between active decisions. "Use REST" and "use GraphQL" both active? Tropelex catches it.

Personas NEW

Synthesize readable persona summaries from agent proficiency tracking. "This agent tends to over-engineer auth flows."

Federation NEW

Opt-in, privacy-preserving sharing of structural statistics across Tropelex installs. "Projects using FastAPI+Postgres have a 12% reversal rate."

Deep Research NEW

Two independent research engines, side by side, plus a hybrid mode that merges them:

  • Multi-Source Scan — the last30days engine. Searches Reddit, X, YouTube, GitHub, HackerNews, Polymarket, and web grounding in parallel, then synthesizes findings into a narrative brief with source citations and key patterns. 1–3 minutes.
  • Citation-Grade Web Research — powered by web-researcher-mcp, spoken to directly over its MCP stdio protocol. Runs an iterative search → LLM-refined follow-up query → search again loop, and imports every real, verifiable source URL straight into the Tropebook citation library. Requires the web-researcher-mcp binary on PATH — free via the DuckDuckGo provider with no key, or point it at Brave with BRAVE_SEARCH_API_KEY for higher rate limits.
  • Hybrid — runs both engines concurrently on the same query, then has the project's LLM backend deduplicate and merge them into one report. If one engine fails, the other's results (and citations) are still returned — the merge degrades gracefully rather than failing outright.
  • Deep research feeds — select "Deep Research" as the provider when creating a feed for scheduled multi-source runs
  • Research history — all multi-source runs are saved; click any previous run to view its output
  • Source keys — configure xAI, ScrapeCreators, Bluesky, and more in Settings → Deep Research Sources for best multi-source coverage

Free sources (HackerNews, GitHub, Polymarket, YouTube, DuckDuckGo) work without any keys. Additional sources and providers unlock with API keys.

Emacs Integration NEW

Capture decisions, friction signals, and git commits directly from Emacs. Zero external dependencies — uses only built-in Emacs libraries.

  • C-c t c — Capture a decision with auto-detected context (file, project, major mode, code context)
  • C-c t r — Capture selected region as decision context (code snippet, log output)
  • C-c t f — Scan current buffer for friction signals
  • C-c t g — Capture current HEAD commit as a decision
  • C-c t s — Check server connectivity and current project
  • C-c t p — Override project name for the session

Automatic capture (when mode is on):

  • Compilation errors — auto-scans compilation output for friction when a build fails. High friction (>30%) triggers a minibuffer alert.
  • Rapid saves — 5+ file saves within 5 seconds triggers a friction signal ("rapid iteration detected").
  • Git commits via Magit — after every magit commit, the message (50+ chars) is auto-captured as a Tropelex decision with diffstat context.

Code context (LSP / treesit / which-function):

  • Captures include current function name and type when available
  • Uses eglot or lsp-mode for symbol info, falls back to treesit (Emacs 29+) or which-function-mode
  • Set tropelex-include-code-context to nil to disable

Setup:

(add-to-list 'load-path "~/Tropelex/emacs")
(require 'tropelex-capture)
(tropelex-capture-mode 1)

Project auto-detects from: projectile → vc-root-dir → directory name fallback. Override with C-c t p.

API Reference

All features expose REST API endpoints. The server runs at http://localhost:8766.

See /openapi.json for the full OpenAPI specification with all 152 endpoints.

Architecture

Tropelex is built with:

  • FastAPI — REST API server
  • JSON files — storage with file-level locking (fcntl.flock)
  • D3.js — knowledge graph visualization
  • Pure functions — all business logic is side-effect free
  • Result type — explicit error handling (Ok/Err)
