Tropelex Documentation

Getting Started

1. Create a Project

Projects are the top-level container for all memory. Go to Memory in the sidebar and click New Project.

2. Record Decisions

Decisions are the foundation. Click + Add Decision in the Memory section. Each decision has:

  • Decision text — what you decided (e.g., "Using Python + FastAPI for backend")
  • Context — why you decided it (optional but recommended)

3. End Sessions

When you finish a work session, click + End Session to summarize what you did. This helps Tropelex learn your patterns.

4. Configure API Keys (Optional)

For web research features, set these environment variables:

  • BRAVE_SEARCH_API_KEY — for Brave Search (free tier available). Also used by citation-grade Deep Research when set, in preference to the free but more rate-limited DuckDuckGo default.
  • OPENAI_API_KEY — for embeddings and LLM-backed features (query refinement, hybrid research merge, AI compression) — optional, dictionary/concatenation fallbacks exist

5. Pick your interface

This page describes the web dashboard, but it's one of five ways in — pick whichever fits how you work: the MCP Server (any MCP-capable agent), the Terminal UI (tmux-first), OpenCode slash commands, the CLI, or Emacs. All five talk to the same running server and the same project memory — nothing is interface-specific.

Features

Tropebook

Research knowledge base. Add citations, search locally or on the web, and build a knowledge graph.

Memory

View and manage project memory — decisions, sessions, preferences, and patterns.

Patterns

Auto-detected patterns from your usage. Tropelex learns what categories you work in, what days you're most active, and more.

Knowledge Graph

Visual D3 force-directed graph of decisions and their relationships (supersedes, caused_by, related_to).

Health Dashboard

Project health score based on decision confidence, session coverage, and pattern detection accuracy.

Impact Analysis

See which decisions have the most downstream impact and track reversal rates.

Ghost Decisions

Detect when code silently drifts from documented decisions. Compares decision keywords against git diffs.

Pre-Write Guard NEW

Check a proposed diff against active decisions before writing code. Prevention is better than detection.

"Why Do We...?" Chat

Ask natural language questions about architectural decisions. Fuses RAG + decision tree + impact analysis into causal answers.

Agent Handoff

Generate role-aware context bundles when one agent hands off to another. Token-budget-aware, role-specific.

Friction Mining NEW

Detect frustration signals in session transcripts — rephrasing patterns, retry loops, escalation markers. No explicit logging needed.

Rationale Check NEW

Fact-check decision rationale against the live web. If your rationale is "chose Postgres for JSON support," Tropelex checks if that's still true.

Memory Compaction NEW

Collapse superseded decision chains into epoch summaries. Keeps memory lean as projects age.

Context Prefetch NEW

Predict the ideal minimal context bundle for a task, sized to a token budget, prioritized by impact score.

Cost Ledger NEW

Track actual dollars and tokens spent per decision. ROI scoring with real denominators.

PR Bot NEW

Generate PR comments with relevant decision context and ghost warnings. Distribution channel for insights.

Narrative Mode NEW

Generate readable prose from the decision graph. Audience presets: new hire, investor, product manager.

Decision Market NEW

Place confidence bets on decisions and track calibration over time. Gamifies retrospective honesty.

Slack Capture NEW

Capture decisions from chat messages and extract implicit decisions from threads.

Time Travel NEW

Check out project memory as of any past date. Forensic tool for postmortems.

Contradictions NEW

Scan for unresolved contradictions between active decisions. "Use REST" and "use GraphQL" both active? Tropelex catches it.

Doc Mining NEW

Scans every markdown file in the repo (excluding node_modules, venvs, .git, caches, and memory/) for three things, reusing the same matching engine as Contradictions rather than a separate one:

  • Doc vs. decision — a doc claims something that contradicts an active, recorded decision
  • Doc vs. doc — two different markdown files contradict each other
  • Uncaptured decisions — a decision-shaped statement ("we must...", "we use...") sitting in prose that never made it into the decision graph at all — candidates worth importing

Findings are severity-ranked the same way Contradictions are (high/medium/low); the UI shows high+medium by default. Trigger a scan from the Doc Mining section, or directly:

curl -X POST http://localhost:8766/api/memory/<project>/docmine/scan -d '{}'

Pass {"paths": ["README.md", "docs/"]} to scan specific files/directories instead of the whole repo.

Personas NEW

Synthesize readable persona summaries from agent proficiency tracking. "This agent tends to over-engineer auth flows."

Federation NEW

Opt-in, privacy-preserving sharing of structural statistics across Tropelex installs. "Projects using FastAPI+Postgres have a 12% reversal rate."

Deep Research NEW

Two independent research engines, side by side, plus a hybrid mode that merges them:

  • Multi-Source Scan — the last30days engine. Searches Reddit, X, YouTube, GitHub, HackerNews, Polymarket, and web grounding in parallel, then synthesizes findings into a narrative brief with source citations and key patterns. 1–3 minutes.
  • Citation-Grade Web Research — powered by web-researcher-mcp, spoken to directly over its MCP stdio protocol. Runs an iterative search → LLM-refined follow-up query → search again loop, and imports every real, verifiable source URL straight into the Tropebook citation library. Requires the web-researcher-mcp binary on PATH — free via the DuckDuckGo provider with no key, or point it at Brave with BRAVE_SEARCH_API_KEY for higher rate limits.
  • Hybrid — runs both engines concurrently on the same query, then has the project's LLM backend deduplicate and merge them into one report. If one engine fails, the other's results (and citations) are still returned — the merge degrades gracefully rather than failing outright.
  • Deep research feeds — select "Deep Research" as the provider when creating a feed for scheduled multi-source runs
  • Research history — all multi-source runs are saved; click any previous run to view its output
  • Source keys — configure xAI, ScrapeCreators, Bluesky, and more in Settings → Deep Research Sources for best multi-source coverage

Free sources (HackerNews, GitHub, Polymarket, YouTube, DuckDuckGo) work without any keys. Additional sources and providers unlock with API keys.

Emacs Integration NEW

Capture decisions, friction signals, and git commits directly from Emacs. Zero external dependencies — uses only built-in Emacs libraries.

  • C-c t c — Capture a decision with auto-detected context (file, project, major mode, code context)
  • C-c t r — Capture selected region as decision context (code snippet, log output)
  • C-c t f — Scan current buffer for friction signals
  • C-c t g — Capture current HEAD commit as a decision
  • C-c t s — Check server connectivity and current project
  • C-c t p — Override project name for the session

Automatic capture (when mode is on):

  • Compilation errors — auto-scans compilation output for friction when a build fails. High friction (>30%) triggers a minibuffer alert.
  • Rapid saves — 5+ file saves within 5 seconds triggers a friction signal ("rapid iteration detected").
  • Git commits via Magit — after every magit commit, the message (50+ chars) is auto-captured as a Tropelex decision with diffstat context.

Code context (LSP / treesit / which-function):

  • Captures include current function name and type when available
  • Uses eglot or lsp-mode for symbol info, falls back to treesit (Emacs 29+) or which-function-mode
  • Set tropelex-include-code-context to nil to disable

Setup:

(add-to-list 'load-path "~/Tropelex/emacs")
(require 'tropelex-capture)
(tropelex-capture-mode 1)

Project auto-detects from: projectile → vc-root-dir → directory name fallback. Override with C-c t p.

MCP Server NEW

Everything the dashboard, VSCode extension, and Emacs package do over Tropelex's REST API is also available as MCP tools, so any MCP-capable agent — Claude Code, Cursor, Claude Desktop — can read and write project memory directly, without a bespoke per-editor integration. Lives in mcp_server/, in its own venv kept separate from Tropelex's own system-Python server.

Setup

cd mcp_server
uv venv .venv
uv pip install --python .venv/bin/python -r requirements.txt

Registering it

A project-scoped .mcp.json is committed at the repo root — anyone who clones Tropelex and opens it in Claude Code gets the tropelex MCP server automatically (it shells out to mcp_server/run.sh, which resolves its own venv relative to the repo, so no machine-specific absolute paths are baked in). No manual registration needed for Claude Code.

To register it elsewhere:

claude mcp add tropelex -- /path/to/Tropelex/mcp_server/.venv/bin/python /path/to/Tropelex/mcp_server/server.py

Requires the main Tropelex server running. Point at a non-default instance with the TROPELEX_URL environment variable.

Terminal UI NEW

A Textual-based terminal dashboard in tui/ for anyone who lives in tmux rather than an editor — browse projects, read decision history, capture new decisions, all over the same REST API every other interface uses. Own venv.

Setup & run

cd tui
uv venv .venv
uv pip install --python .venv/bin/python -r requirements.txt
.venv/bin/python app.py

Keybindings

KeyAction
↑ / ↓Move between projects (sidebar) or decisions (table)
EnterSelect a project
aCapture a new decision (modal — decision text + optional context)
rRefresh the current view

Shows the project sidebar (from GET /api/memory), a decision table for the selected project (most recent first, with confidence tier), and a status bar with decision count and unresolved contradiction count. First pass, not a full port of the dashboard — covers the core browse/capture loop.

OpenCode Integration NEW

Slash commands and a startup hook for using Tropelex from inside OpenCode. Defined in .opencode/ in this repo.

Setup required — OpenCode only loads plugins it's told about. Copy the plugin and register it: 
cp plugins/tropelex.js ~/.config/opencode/plugins/tropelex.js
Then add "tropelex" to the "plugin" array in ~/.config/opencode/opencode.json (and opencode.jsonc, if you have one — whichever OpenCode reads on your setup). Restart OpenCode to pick it up. If commands you expect aren't showing in the command palette, this is the first thing to check.
CommandWhat it does
/tropelex-record-decisionRecord a decision: /tropelex-record-decision Using PostgreSQL for database
/tropelex-end-sessionSummarize the session and trigger pattern learning: /tropelex-end-session Built user auth with JWT
/tropelex-show-contextPrint the accumulated context for the current project (decisions, sessions, patterns, tech stack) — same context that's auto-injected into new sessions
/tropelex-contextRun raw queries against project memory, insights, and recent decisions
/tropelex-upCreate/update a project's memory record (name, description, tech stack)

Project name is auto-detected from the workspace folder name (or git remote, if the plugin's detectProject() finds one) — each workspace gets its own isolated memory. Override with the TROPELEX_PROJECT environment variable.

The startup hook (plugins/tropelex.js) also compresses prompts over a configurable length threshold and injects project context before every prompt automatically — see the file header for the full list of environment variables (TROPELEX_URL, TROPELEX_COMPRESS_MIN, TROPELEX_INJECT_CONTEXT).

API Reference

All features expose REST API endpoints. The server runs at http://localhost:8766.

See /openapi.json for the full OpenAPI specification with all 152 endpoints.

Architecture

Tropelex is built with:

  • FastAPI — REST API server
  • JSON files — storage with file-level locking (fcntl.flock)
  • D3.js — knowledge graph visualization
  • Pure functions — all business logic is side-effect free
  • Result type — explicit error handling (Ok/Err)

Troubleshooting

"Cannot reach Tropelex" / connection refused

The server isn't running. Start it from the repo root:

python3 -m core.tropebook.web.server

Every interface (dashboard, MCP server, TUI, OpenCode plugin, Emacs package, CLI-for-server-backed-features) talks to http://localhost:8766 by default. If you're running it elsewhere, set TROPELEX_URL for whichever client needs it.

MCP server or TUI won't start / ModuleNotFoundError

Both live in their own venv, separate from Tropelex's own system Python — the venv wasn't created, or dependencies weren't installed into it. From the relevant directory:

uv venv .venv
uv pip install --python .venv/bin/python -r requirements.txt

This project runs on a system Python that's externally managed (Debian/Ubuntu-style) — plain pip install at the system level will refuse to run. That's exactly why the MCP server and TUI each get an isolated venv instead.

OpenCode commands missing from the palette

See the OpenCode Integration section above — the plugin has to be copied to ~/.config/opencode/plugins/ and registered in opencode.json's "plugin" array. It isn't picked up automatically just by being in this repo.

Settings show a key as "configured" that you never entered

Check your shell profile (~/.bashrc, ~/.zshrc) and any other .env files on the machine (e.g. ~/.config/last30days/.env) for a stray export — environment variables set outside Tropelex's own .env still get picked up, since Settings reads from the process environment, not just the one file. This is usually a leftover from setting up a different tool, not a Tropelex bug.

Deep Research citation-grade mode is rate-limited

The free DuckDuckGo provider rate-limits aggressively under repeated use. Set BRAVE_SEARCH_API_KEY — Tropelex prefers Brave for web-researcher-mcp automatically when it's present.

A feature shows "no data yet" and nothing happens when I try it

Several features are empty by design until they're seeded — Decision Market needs a bet placed, Time Travel needs at least one recorded session (+ End Session in the Memory tab), Personas need a skill outcome recorded. This is normal for a fresh project, not a bug.
